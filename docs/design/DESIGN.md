# ACDC Portal – design guide

Visual direction: **Arctic clean** (decided 2026-11-02). Light, airy content surfaces;
a deep arctic-navy top bar that carries the white logo; one aurora-teal accent; soft
shadows; automatic dark mode that follows the device setting. Consistent Lucide line
icons instead of emoji.

## Identity

- Product: **ACDC Portal** – Arctic Cloud Developer Challenge.
- Logo: `src/images/ACDCLogo.png` (white wordmark, for dark backgrounds: the top bar and admin sidebar).
- Favicon: `src/images/favicon.svg`.
- Tone: friendly, clear, hackathon energy. Not corporate, not flashy. Copy in sentence case.
- Two surfaces, one brand:
  - **Participant portal** – events, event/team page, registration, invitations.
  - **Admin area** – `admin-*.html`, sidebar layout.

## Files

| File | Owns |
|---|---|
| `src/css/tokens.css` | Tokens (`:root`) and the dark palette. Loaded first by **every** page |
| `src/css/styles.css` | Portal base, app shell (top bar, page hero), shared components |
| `src/css/portal.css` | Participant page components (event cards, team grid, badges tab, registration steps) |
| `src/css/admin-styles.css` | Admin layout (sidebar + mobile drawer, page header, panels, tables, stat cards) |
| `src/images/icons.svg` | Lucide icon sprite, generated by `scripts/build-icons.js` (`npm run build:icons`) |
| `src/js/site-header.js` | Participant app shell markup (top bar, avatar menu, page hero) |
| `src/js/admin-sidebar.js` | Admin sidebar markup |

Pages must not carry their own `<style>` blocks or hardcoded colours. Migrate any that
remain into the files above when you touch a page.

## Tokens – one shared set

Defined **once** in `:root` in `src/css/tokens.css`. Never hardcode a colour, radius,
shadow, font size or spacing value in a stylesheet, page or template string – use a token.
Need a new one? Add it to `:root` in `tokens.css` (and the dark block if it is a colour) and list it here.

| Group | Tokens |
|---|---|
| Brand | `--color-navy`, `--color-navy-raised`, `--color-navy-line`, `--color-on-navy`, `--color-on-navy-muted` |
| Surfaces | `--color-bg`, `--color-surface`, `--color-surface-muted`, `--color-surface-hover`, `--color-border`, `--color-border-strong`, `--color-overlay` |
| Text | `--color-text`, `--color-text-muted`, `--color-text-subtle` |
| Accent | `--color-accent`, `--color-accent-hover`, `--color-accent-subtle`, `--color-accent-text`, `--color-on-accent`, `--color-accent-bright` |
| Status | `--color-{success,warning,danger,info,violet}` with `-subtle` (background) and `-text` (text on subtle); `--color-danger-hover` |
| Type | `--font-sans`, `--font-mono`, `--text-xs` … `--text-4xl`, `--leading-tight`, `--leading-normal`, `--weight-medium/semibold/bold` |
| Spacing | `--space-1` (4px) … `--space-16` (64px), 4px grid |
| Shape | `--radius-sm` 6, `--radius-md` 10, `--radius-lg` 14, `--radius-xl` 20, `--radius-full` |
| Depth | `--shadow-xs`, `--shadow-sm`, `--shadow-md`, `--shadow-lg`, `--focus-ring` |
| Motion | `--ease-out`, `--duration-fast` (120ms), `--duration` (200ms) |
| Layout | `--container-narrow` 600px (forms), `--container` 1120px, `--topbar-height` |

Legacy names (`--primary-color`, `--card-bg`, `--text-muted`, `--border-radius`, …) still
resolve as aliases for pages not yet migrated. Do not use them in new code.
`--admin-*` colour variables in `admin-styles.css` are legacy: replace them with the shared
tokens. Do not add new ones.

All text/background pairs used by the tokens meet WCAG AA in light and dark mode (checked
2026-11-02). Keep it that way: muted text on `--color-bg` needs ≥ 4.5:1.

## Dark mode

A page opts in with `<html lang="en" data-theme="auto">` once it uses only tokens
(hardcoded colours would clash). The dark palette lives in the `prefers-color-scheme: dark`
block in `tokens.css`. Check every migrated page in both schemes.

| Tabs | `.tabs` > `.tab` (`.active`) |
| Forms | `.form-group` (label + input/select/textarea), `.input`, `.form-row`, `.checkbox-label`, `.field-hint` |

Reuse an existing component before inventing one. Status colours mean the same everywhere:
success = done/open, info = upcoming, violet = live, warning = needs attention, danger = destructive/error.

## Icons

Lucide (ISC licence), self-hosted as one sprite. Use icons, not emoji, for UI meaning. Emoji
are allowed only as decorative flavour (e.g. the polar-bear "waking the database" loader).
To add an icon: add its Lucide name to `scripts/build-icons.js`, run `npm run build:icons`,
commit the regenerated `src/images/icons.svg`.

## Typography

System stack (`--font-sans`). No web fonts. Body 16px on the portal, 14px in admin.
Headings use `--weight-bold` and slight negative letter spacing.

## Responsiveness and accessibility

- Must work at 360px width and up without horizontal scrolling – including admin.
- WCAG AA contrast, visible focus (`--focus-ring` via `:focus-visible`), semantic HTML.
- Icons are decorative (`aria-hidden`); give icon-only buttons an `aria-label`.
- Respect `prefers-reduced-motion` (handled globally). Animate only `transform` and `opacity`.

## Constraints that come from the rest of the app

- **Strict CSP:** no inline `<script>`, no `on*=` attributes, no `javascript:` URLs. Inline
  `style` attributes are allowed by the policy but avoid them – use classes.
- **Tests pin ids, some classes and some visible text.** Keep element ids and the classes
  scripts and tests use. Run `npm test` and the E2E suite (`npm run test:e2e`, ideally with
  `E2E_CSP=enforce`) before reporting done.

## Verification

1. `npm run dev`, open http://localhost:4280 (`/dev-login` for a signed-in view), or run the
   E2E harness and `node tests/e2e/support/capture-screens.js <outDir>` for screenshots of
   every page per role at desktop and phone width (`SHOTS=<regex>`, `SCHEME=dark`).
2. Check participant and admin pages, desktop and 375px, light and dark.
3. `npm test` and the E2E suite.

- 2026-11-02: Page-specific CSS lives in `portal.css` / `admin-styles.css`, not in `<style>` blocks.

  backdrop, Escape to close); tables scroll inside their panel, never the page.
- 2026-11-02: Event page migrated (inline `<style>` removed). Event facts sit in a band under the page hero.
  Status colours on this page: registration open / approved = success, pre-registration / submitted = info,

  accent, Participant = neutral. Placeholders (add member, unlock slot) are dashed neutral tiles, not tinted.

- 2026-11-03: Admin teams, event participants and interest list migrated (inline `<style>` removed, page
  sections at the end of `admin-styles.css`, `data-theme="auto"`).
- 2026-11-03: In admin tables an event name is a link (`.table-link`) to that event in the event editor;
  no separate "View event" button. Team members expand inline under the row (`.expand-btn` with
  `aria-expanded` and a rotating chevron). Under 640px the teams table becomes stacked cards.
- 2026-11-03: Team fill badge reads "filled / committed" like the dashboard: full = success, no members yet =
  warning, in between = neutral; pending invites sit next to it as muted "+N invited" text. A team opened with
  `?team=<id>` gets `--color-accent-subtle` and a 3px accent bar (also along its member list).
- 2026-11-03: Invitation pending = warning badge, expired = neutral. Interest leads: registered = success,
  verified = info (waiting for registration), unverified = warning. Allergy tags = warning badges; hotel payer and
  roles (judge, committee) = neutral badges; team admin = accent badge; booked hotel night = success check.

  not a tint. Stat icons use `tone-accent` or `tone-neutral` unless the number is itself a status (allergies =

- 2026-11-03: Icon-only buttons that run through `withBusy()` pass no busy label, because the label replaces the
  button's content and would wipe the icon; the disabled state shows progress instead.
